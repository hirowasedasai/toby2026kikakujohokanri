# シート構成

## 入力（書き込み禁止）

| シート | 用途 | 優先度 |
| --- | --- | ---: |
| `26参参フォーム回答` | 通常フォーム回答の生データ | 10 |
| `26運スタ企画フォーム回答` | 運営スタッフ企画フォーム回答の生データ | 10 |
| `26参参変更申請` | 参加団体・参加者企画の変更申請原本 | 自動同期対象外 |
| `26運スタ企画変更申請` | 運営スタッフ企画の変更申請原本 | 自動同期対象外 |

スクリプトは入力タブの作成、ヘッダー補正、値更新、書式変更、削除を一切行わない。4タブのどれか、またはヘッダー行が欠ける場合は同期開始前に停止する。通常提出2タブは`config.gs`の候補ヘッダーで列を解決し、必須列も検証する。`26運スタ企画フォーム回答`の参加企画だけは、フォームに同名質問がないため固定値`運営スタッフ企画`を読み取り時に補う。

変更申請2タブは自由記述を含み、構造化済みの最新状態ではないため、マスターへ自動反映しない。フォーム送信時トリガーも同期を起動せず、権限者が原本を確認してマスターへ明示反映する。

## `26掲載情報マスター`（正本）

| 必須列 | 意味 |
| --- | --- |
| `管理ID` | 正式ID、または`TMP-`で始まる暫定ID。既存更新時は維持 |
| `メールアドレス` | 連絡先。出力と処理ログには含めない |
| `参加企画` | 参加区分。飲食物抽出にも利用 |
| `所属局` | 運営スタッフ企画の所属局。参加団体企画と追加前の回答では空欄可 |
| `団体名` | 掲載団体名 |
| `企画名` | 掲載企画名 |
| `販売物` | 掲載する販売品目 |
| `画像リンク` | 掲載画像へのリンク |
| `データソース` | 採用した入力タブ名 |
| `同期ステータス` | `同期済み`または`要確認` |
| `最終更新日時` | 内容が実際に変わった日時 |
| `要確認` | `TRUE`/`FALSE` |
| `要確認理由` | PIIを含まない制御された理由 |

列順は固定しない。1行目のヘッダー名で位置を解決する。追加列は同期時にそのまま保持する。

## 出力

`参参一覧`の列は`管理ID`、`参加企画`、`所属局`、`団体名`、`企画名`、`販売物`、`画像リンク`、`最終更新日時`。`屋台情報まとめ`は`管理ID`、`参加企画`、`所属局`、`団体名`、`企画名`、`販売物`、`画像リンク`、`要確認`。

どちらもマスターの`同期済み`かつ要確認でない行だけを使う。出力タブのヘッダーはsetupで作成し、通常の出力更新はヘッダーを上書きしない。いずれかの生成結果が0件となり既存データがある場合は、安全弁で既存データを維持する。正当に0件へ変更する場合も、原因確認後に権限者が明示対応する。

## `26処理ログ`

列は`実行ID`、`記録日時`、`環境`、`処理`、`レベル`、`エラーコード`、`入力タブ`、`行番号`、`列名`、`説明`、`新規件数`、`更新件数`、`スキップ件数`、`要確認件数`、`リリースID`。

メール、入力行全体、自由記述本文、画像URLは記録しない。ログ閲覧権限は運用担当者に限定する。
