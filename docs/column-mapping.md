# 列マッピング

実装上の正本は`apps-script/config.gs`である。候補や判定ルールを変更したらこの文書とテストも更新する。

## 入力候補

| 論理項目 | 許容するヘッダー候補 | 必須 |
| --- | --- | --- |
| 正式企画ID | `企画ID`、`正式企画ID`、`管理ID`、`企画番号` | 任意 |
| メール | `メールアドレス`、`メール`、`Email`、`E-mailアドレス` | 必須 |
| 参加企画 | `参加企画`、`参加形態`、`企画区分`、`部門` | 必須 |
| 所属局 | `所属局` | 任意。運スタ企画フォームでは新規回答時に必須 |
| 団体名 | `団体名`、`参加団体名`、`サークル名`、`参加団体・参加者名（17字以内推奨・36字以内）`、`部署名（チーム、PJなど）`、`部署名` | 必須 |
| 企画名 | `変更後企画名`、`企画名`、`掲載企画名`、`催事名`、`企画名（26字以内）`、`企画名（24字以内）` | 必須 |
| 販売物 | `変更後販売物`、`販売物`、`販売品目`、`販売内容`、`飲食物`、`販売物について` | 任意 |
| 画像リンク | `変更後画像リンク`、`画像リンク`、`画像URL`、`画像`、`掲載画像`、`サムネイル画像提出`、`画像提出（飲食サムネイル画像）`、`アイコン画像提出`、`画像提出（飲食アイコン画像）` | 任意 |
| 回答日時 | `タイムスタンプ`、`回答日時`、`申請日時`、`送信日時` | 任意・現在は監査ログへ出さない |

同じ論理項目の候補が複数ある場合は表の左側にある非空値を行ごとに優先し、優先列が空なら次候補へフォールバックする。列番号は保存せず、実行ごとに1行目から解決する。ヘッダー比較はNFKC正規化、trim、空白除去、小文字化を行う。`=`から始まりGoogle Sheetsの数式として評価され得る入力は行エラーとして拒否する。

`26運スタ企画フォーム回答`には参加企画の質問がないため、この入力元に限り`参加企画=運営スタッフ企画`を固定値として補う。`所属局`はマスターの独立列へ、部署名は`団体名`へ、`企画名（26字以内）`は`企画名`へ対応づける。入力タブ自体には書き戻さない。`所属局`追加前の過去回答は空欄のまま受け入れ、空欄で既存マスター値を消さない。

`26参参フォーム回答`では、一般企画用と飲食企画用に分かれた企画名・画像列を行ごとの非空値で解決する。画像はサムネイルをアイコンより優先し、一般用と飲食用のうち回答が入っている列を採用する。

入力フォームでは、同期対象外の質問見出しが重複していても処理を継続する。同期対象の候補見出しが同名で複数ある場合は、候補優先順と左からの列順で各行の最初の非空値を採用する。マスター、出力、処理ログの管理タブでは重複ヘッダーを引き続きエラーとして停止する。

`26参参変更申請`と`26運スタ企画変更申請`は、変更前・変更後を自由記述で提出する形式であり、列単位の最新状態へ安全に変換できない。この2タブには列マッピングを適用せず、自動同期対象外とする。運スタ企画変更申請では`所属局`を回収するが、確認時の振り分け情報として保持し、マスターへ自動反映しない。

## マスターへの反映

- 正式企画IDあり: 正式IDをキーにし、新規行の`管理ID`にも使う。
- 正式企画IDなし: 正規化したメールと参加企画を暫定キーにし、決定的な`TMP-`管理IDを作る。
- 同じ正式IDの複数入力: 優先度の高い入力を採用する。同一タブでは後の行を採用する。
- 所属局・販売物・画像リンクが空: 既存値を維持する。
- 内容に差がない: 更新日時を変えずスキップする。
- 衝突・キー変更疑い: 自動統合せず要確認にする。

## 飲食物販売企画の判定

次の両方を満たすマスター行だけを`屋台情報まとめ`へ出す。

1. `参加企画`が`飲食物販売企画`、`飲食販売企画`、`模擬店`、`屋台`のいずれか、または`飲食`、`食品`、`模擬店`、`屋台`のいずれかを含む。
2. `販売物`が空でない。

さらに共通条件として`同期ステータス=同期済み`かつ`要確認`でないことが必要。販売物本文から飲食かどうかを推測せず、参加区分を基準にする。
