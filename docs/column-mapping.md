# 列マッピング

実装上の正本は`apps-script/config.gs`である。候補や判定ルールを変更したらこの文書とテストも更新する。

## 入力候補

| 論理項目 | 許容するヘッダー候補 | 必須 |
| --- | --- | --- |
| 正式企画ID | `企画ID`、`正式企画ID`、`管理ID`、`企画番号` | 任意 |
| メール | `メールアドレス`、`メール`、`Email`、`E-mailアドレス` | 必須 |
| 参加企画 | `参加企画`、`参加形態`、`企画区分`、`部門` | 必須 |
| 所属局 | `所属局` | 任意。運スタ企画フォームでは新規回答時に必須 |
| 団体名 | `団体名`、`参加団体名`、`サークル名`、`参加団体・参加者名（17字以内推奨・36字以内）`、`部署名（チーム、PJなど）`、`部署名` | 必須 |
| 企画名 | `変更後企画名`、`企画名`、`掲載企画名`、`催事名`、`企画名（26字以内）`、`企画名（24字以内）` | 必須 |
| 販売物 | `変更後販売物`、`販売物`、`販売品目`、`販売内容`、`飲食物`、`販売物について` | 任意 |
| 画像リンク | `変更後画像リンク`、`画像リンク`、`画像URL`、`画像`、`掲載画像`、`サムネイル画像提出`、`画像提出（飲食サムネイル画像）`、`アイコン画像提出`、`画像提出（飲食アイコン画像）` | 任意 |
| 回答日時 | `タイムスタンプ`、`回答日時`、`申請日時`、`送信日時` | 任意・現在は監査ログへ出さない |

同じ論理項目の候補が複数ある場合は表の左側にある非空値を行ごとに優先し、優先列が空なら次候補へフォールバックする。列番号は保存せず、実行ごとに1行目から解決する。ヘッダー比較はNFKC正規化、trim、空白除去、小文字化を行う。`=`から始まりGoogle Sheetsの数式として評価され得る入力は行エラーとして拒否する。

`26運スタ企画フォーム回答`には参加企画の質問がないため、この入力元に限り`参加企画=運営スタッフ企画`を固定値として補う。`所属局`はマスターの独立列へ、部署名は`団体名`へ、`企画名（26字以内）`は`企画名`へ対応づける。入力タブ自体には書き戻さない。`所属局`追加前の過去回答は空欄のまま受け入れ、空欄で既存マスター値を消さない。

`26参参フォーム回答`では、一般企画用と飲食企画用に分かれた企画名・画像列を行ごとの非空値で解決する。画像はサムネイルをアイコンより優先し、一般用と飲食用のうち回答が入っている列を採用する。

## 参参一覧への照合

前年の`25参参一覧`は、申込時の参加企画・メールアドレス・参参名を基準に、`25参参フォーム回答`のメールアドレスから参参名を取得し、参加企画と参参名から企画名を取得して確定版を作る提出管理表だった。今年は同じ関係をセル数式ではなく差分同期で実装する。

| 参参一覧 | 入力・扱い |
| --- | --- |
| `参加企画` | 申込台帳。同期で上書きしない |
| `提出状況` | 一致=`提出済み`、未回答=`未提出`、不一致・重複=`確認中`。`キャンセル`と人が設定した`確認中`は保持 |
| `メールアドレス` | 申込台帳か、一覧にない回答の初回追加時にフォームから設定 |
| `参参名・参加申し込み時` | 申込台帳。同期で上書きしない |
| `参参名・フォーム回答` / `企画名・フォーム回答` | `26参参フォーム回答`から取得する監査用の自動列 |
| `参参名・確定版` / `企画名・確定版` | 一意なフォーム回答を反映する自動列 |
| `照合結果` | `一致`、`未提出`、`参参名差異`、`申込情報未登録`、`一覧内重複`、`フォーム回答重複`、`申込情報不備` |
| `最終同期日時` | 提出状況または自動列が実際に変わった日時 |

照合は正式企画IDの有無にかかわらず、正規化した`メールアドレス + 参加企画`で行う。列位置は双方の1行目ヘッダーから解決し、入力タブには書き戻さない。前年にあった提出遅延フォーム用列は、今年の入力タブに対応するフォームがないため追加しない。

入力フォームでは、同期対象外の質問見出しが重複していても処理を継続する。同期対象の候補見出しが同名で複数ある場合は、候補優先順と左からの列順で各行の最初の非空値を採用する。マスター、出力、処理ログの管理タブでは重複ヘッダーを引き続きエラーとして停止する。

`26参参変更申請`と`26運スタ企画変更申請`はマスターへの自動同期対象外とする。運スタ企画変更申請だけは、`項目名：「内容」`の記法を厳格に解析し、局別タブへ差分反映するメモリ上の企画情報へ適用する。回答原本とマスターは書き換えない。

## 局別タブへの反映

`26運スタ企画フォーム回答`の`所属局`を、`会場整備局`、`参加対応局`、`開発局`、`企画局`、`広報制作局`、`渉外局`、`総務局`、`財務局`、`超局PJ`の完全一致で9タブへ振り分ける。列番号は固定せず、回答タブの1行目ヘッダーから解決する。

変更項目として、企画名、企画紹介文、担当者名、所属局、部署名、企画場所、企画時間・各日開始終了時刻、その他企画日時、企画ジャンル、メインジャンル、整理券、ゲスト各項目、備考と、その既存フォーム・前年表記の別名を許可する。変更前後で同じ項目集合を要求し、全項目の現在値が変更前と一致した場合だけ一括適用する。一部だけ先に適用することはない。変更後企画名の重複と未登録所属局も拒否する。

局別タブの手動管理列は`内部向け企画・取り組み名`、`掲載文字情報`、`ページ名`、`掲載媒体`、`当媒チェック`、`校閲チェック`とする。差分同期はこの6列を既存行から企画名で引き継ぎ、自動管理列だけを更新する。`掲載文字情報`は`企画紹介文`の別名として扱わず、変更申請に記載されても自動反映しない。

局別タブの表示順は前年タブの業務順を基準にする。前年の`外部向け企画・取り組み名`は`企画名`、`責任者名`は`担当者名`、`チーム・班`は`部署名`、`変更申請反映`は`変更反映状況`、`企画実施日`は`企画日時`へ対応する。前年にない詳細列は右端へ置き、`フォーム提出`は重複管理しない。

手動列のうち`掲載媒体`は`パンフレット`、`Webサイト`、`パンフ／Web`の選択式とし、`当媒チェック`と`校閲チェック`は4段階の確認状態を選択する。入力規則の付与先も列番号ではなく1行目のヘッダー名から解決する。列順変更前の入力規則は一度クリアし、`整理券情報`や`ゲスト情報`など移動後の別列へ残さない。

企画名不一致・重複、所属局または部署名不一致、記法不正、変更項目不一致、現在値不一致、画像変更は`26要手動確認`へ送る。メールアドレスは局別タブと要手動確認タブへ出力しない。

## マスターへの反映

- 正式企画IDあり: 正式IDをキーにし、新規行の`管理ID`にも使う。
- 正式企画IDなし: 正規化したメールと参加企画を暫定キーにし、決定的な`TMP-`管理IDを作る。
- 同じ正式IDの複数入力: 優先度の高い入力を採用する。同一タブでは後の行を採用する。
- 所属局・販売物・画像リンクが空: 既存値を維持する。
- 内容に差がない: 更新日時を変えずスキップする。
- 衝突・キー変更疑い: 自動統合せず要確認にする。

## 飲食物販売企画の判定

次の両方を満たすマスター行だけを`屋台情報まとめ`へ出す。

1. `参加企画`が`飲食物販売企画`、`飲食販売企画`、`模擬店`、`屋台`のいずれか、または`飲食`、`食品`、`模擬店`、`屋台`のいずれかを含む。
2. `販売物`が空でない。

さらに共通条件として`同期ステータス=同期済み`かつ`要確認`でないことが必要。販売物本文から飲食かどうかを推測せず、参加区分を基準にする。
