# 既存画像処理の管理

本番だけに存在した画像処理を2026-09-06にGitへ取り込んだ。`processImages`と`resizeAHColumnImagesToSpecificFolder`の呼び出し名を保持する。局別同期・フォーム送信trigger・runAllからは実行しない。画像処理の実行は別途依頼されたときだけ行う。

`26参参フォーム回答`の`画像提出（飲食アイコン画像）`と`参加団体・参加者名（17字以内推奨・36字以内）`を1行目ヘッダーから解決し、列移動を許容する。重複・欠落するヘッダーでは開始前に停止する。原本画像を作業用Driveフォルダへコピーし、Drive APIの認証付きサムネイルで300×300正方形クロップを取得して保存する。複数リンクがある場合は従来どおり先頭だけ処理する。

Script Propertiesに`IMAGE_STAGING_FOLDER_ID`、`IMAGE_OUTPUT_FOLDER_ID`、旧関数用の`IMAGE_LEGACY_OUTPUT_FOLDER_ID`を設定する。実IDはGitに保存しない。旧関数の画像変形はSlidesによる引き伸ばしから同じDriveクロップ方式へ統一し、`Resized_300x300_`のファイル名接頭辞を保持する。通常関数では参参名と同一実行内の連番をファイル名に使う。繰り返し実行するとコピーが追加される一括処理であり、再実行前に保存先を確認する。

回答タブへのリンク上書き、共有範囲の拡大、原本ファイル削除は行わない。作業用コピーも残す。保存画像は保存先フォルダの権限を継承する。行エラーは処理ログに行番号と固定メッセージだけを記録し、担当者名・団体名・URL・ID・生の例外を記録せず後続行を継続する。

Drive v3の高度なサービスと、本番ですでに使われていたspreadsheets・drive・script.external_requestスコープを保持し、同期trigger管理用のscript.scriptappを戻す。外部取得は画像処理ファイルだけに限定し、Googleのgoogleusercontent.com配下のサムネイルURL以外を拒否する。認証ヘッダー付きリクエストはリダイレクトを追跡しない。第三者サービスや外部runtime依存は追加しない。
