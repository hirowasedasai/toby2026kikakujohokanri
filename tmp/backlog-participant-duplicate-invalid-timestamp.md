# Backlog: フォーム再送による回答重複の自動解決

- 状態: 完了
- 作成日: 2026-09-01
- 更新日: 2026-09-02
- 対象: `26掲載情報マスター`、`参参一覧`の差分同期
- 個人情報: 本文には記載しない

## 背景

同じ提出者・参加企画・企画名に対するフォーム再送が、`参参一覧`で`確認中 / フォーム回答重複`のまま残る事例がある。

確認した事例は次の2種類だった。

- 正常な回答日時を持つ複数回答があり、後の回答で紹介文・ジャンル・SNS等が更新されている。
- 旧回答の日時セルに回答日時ヘッダー文字列が入り、正常な日時を持つ後続回答で内容・画像が更新されている。

## 採用した解決方針

次をすべて満たす複数回答は同一企画の再送として扱い、回答日時が一意に新しい回答を採用する。

- 同じ入力タブの回答である。
- 正規化したメールアドレス・参加企画・企画名から作る暫定キーが一致する。
- 最新の正常な回答日時が一意に決まる。

変更項目は画像リンクだけに限定しない。フォームを再送して内容を更新する運用を許容し、最新回答を現在値として扱う。

回答日時は次の3種類に分類する。

- `valid`: 日付として解釈できる。
- `header-placeholder`: 正規化後の値が設定済みの回答日時候補ヘッダーと一致する。
- `invalid`: 上記以外の解釈不能値。

`header-placeholder`を含んでも、他に一意な最新の正常日時があれば採用する。`invalid`を含む場合、または最新日時が同率の場合は自動統合せず、`フォーム回答重複`のまま人力確認へ残す。

## 実装内容

- マスター同期と`参参一覧`同期で同じ再送解決ロジックを使用する。
- 採用した最新回答でマスターの旧衝突状態を解除する。
- `参参一覧`を`提出済み / 一致`へ戻し、フォーム回答列と確定版を更新する。
- 自動解決時はPIIを含まないINFOログだけを残す。
- 入力フォーム回答タブには一切書き込まない。

## 安全条件

- 任意の不正日時を行番号だけで新旧判定しない。
- 同時刻の回答を行番号だけで選ばない。
- 入力タブをまたぐ回答を再送として統合しない。
- 列位置は1行目のヘッダー名から解決する。
